日期：2026-10-16（Asia/Taipei）。本报告仅对应第一阶段，不代表正式发行验收。

- 开发机：Windows NT 10.0.26300.0（非目标 Windows 10 22H2）。
- AMD Ryzen 9 9950X3D，32 逻辑处理器，约 47.6 GiB 物理内存。
- 已装 Framework Release=534296（4.8.1）；4.8 Developer Pack 通过 Winget 安装。
- 使用 Framework64 MSBuild 4.8.10001.0、4.8 引用程序集，目标 x64。
- 最终构建命令：`./build.ps1 -Test -OutputDirectory artifacts/verified`。
- 最终构建与测试退出码 0，未报告编译警告或错误。
- EXE 15,872 字节，配置 281 字节，无第三方运行库。
- 运行时检查脚本通过：Framework >= 4.8、x64。

构建过程中，沙箱内旧 MSBuild 处理项目引用时发生内部缓存错误；在正常本机权限下构建成功。
另一次构建因运行中的 EXE 被占用而未完成；保留原窗口和笔迹，将最终构建输出到上述独立目录后成功。
没有终止用户的白板窗口。

## 运行窗口检查

通过 computer-use 技能使用鼠标和键盘操作独立验证实例，观察到：

- 原生 WPF 窗口和纯色绿板、底部工具栏正常显示。
- 默认鼠标拖动产生连续白色细线。
- 选择红色和 16 DIP 后，鼠标拖动产生明显较粗红线；原白线保留。
- 32 DIP 橡皮在测试红线中央擦出缺口，其他部分保留。
- 隐藏工具栏后出现“显示工具栏”按钮，可恢复工具栏。
- F11 退出全屏显示正常系统标题栏，再次 F11 填充屏幕；笔迹维持画布坐标。
- 检查过约 1100 × 720 的窗口布局以及 2560 × 1440 的全屏画面。

自动化工具点击下拉弹出列表时曾报告坐标超出窗口边界；重新观察后通过 End/Enter 完成粗细切换。
这是本次自动化工具对弹出窗口坐标的限制，未据此声称已完成真实触屏下拉选择验证。

## 资源测量（单次开发机样本）

验证实例运行窗口完成上述少量笔迹操作后采样：

| 指标 | 实测 |
| --- | --- |
| 工作集 WorkingSet64 | 107.73 MiB |
| 私有字节 PrivateMemorySize64 | 199.34 MiB |
| 私有工作集 WorkingSetPrivate | 42,283,008 字节，约 40.32 MiB |
| 约 5.03 秒期间 CPU 时间增量 | 125 ms |
| 换算单核平均 CPU | 约 2.49% |
| 换算全机 32 线程平均 CPU | 约 0.078% |

工作集、私有字节和私有工作集是不同指标，不能混用。
私有工作集通过 Win32_PerfRawData_PerfProc_Process 按 PID 读取，与前一组进程指标先后采样，非完全同时。
这是短时样本，桌面自动化可能影响结果，不能作为长期空闲、无内存泄漏或学校旧设备性能结论。
启动耗时、持续书写 CPU、60FPS、触摸延迟、数千笔迹响应尚未实测。
